# simf — Project History Archive

This file consolidates the exhaustive session-by-session history that used to
live directly inside `CONTRIBUTING.md` and `ROADMAP.md`. Both files had grown into
running changelogs — some single bullets exceeded 8,000 characters — which
cost real context budget on every session without being needed for day-to-day
work, and the two files had started duplicating and drifting on the same
"current state" claims. This archive preserves that history **verbatim**
(nothing summarized or dropped); `CONTRIBUTING.md` and `ROADMAP.md` now carry only
current, forward-looking content plus a pointer here.

**Before treating anything below as the full story**, check whether it
already has a dedicated writeup: most of the significant findings here have
either a `docs/validation/*.md` doc (cited inline below) or a persistent
memory entry (see `MEMORY.md` in the memory system) with more detail and, in
some cases, corrections made after this text was written. Treat dates/numbers
here as historical — cross-check against the current `CONTRIBUTING.md` for
anything you're about to act on.

Archived 2026-07-28, in four blocks, in the order they originally appeared.

Replaces `core/marginals.py:ehp_marginals()` — closed-form derivative of

| Commit | Item |
|---|---|
| _staged_ | `core/survivability_weights.py` + 10 anchor tests + `_marginals_for` cache in `app.py` (4 call sites) + `SIMF_FAST_MARGINALS` test bypass |

**Numbers for Brutoh (Prot Warr) after the fix, per +1 rating on physical pressure:**
vers 311 > armor 246 > strength 91 > haste 81 > mastery 80 > stam 71 > crit 9.
Previously every secondary except vers returned 0. A +1000 mastery piece now
gets +80k eHP credit it was previously missing; +1000 haste +81k; +1000 strength +91k.

**Defense of the eHP units.** Stamina has an exact closed-form derivative
(`hp_per_stam / ((1 - armor_dr)(1 - vers_dr))` — paper-math rock-solid).
After running the sim's ETMI-12 perturbation against an all-physical and
an all-magic projection of the damage profile, the function anchors:
`K = closed_form_dEHP_per_stam / sim_dETMI_per_stam`. Every other stat's
eHP-equivalent marginal is `(sim_weight / sim_stam) × closed_form_dEHP_per_stam`.
Armor and versatility have closed-form too — they serve as independent
sanity checks in `tests/test_survivability_weights.py` (armor within ±2x,
vers within ±5x of closed-form; deviations above that indicate ETMI
exp-saturation and the result is flagged unreliable).

**Cost.** ~10–15 s on Pi via 4-worker ProcessPoolExecutor on character
load, behind a `st.spinner("Calibrating stat weights for this character…")`.
Cached per character signature + `constants_version` so subsequent reads
are free. Falls back to closed-form transparently if the sim path errors
or the stamina anchor can't be established.

report sim mastery/haste/crit ≈ 0 because their spec modules don't scale
Death Strike / Soul Cleave / etc. with those stats. This is an engine
fidelity gap in `classes/*.py`, not a survivability_weights bug — the
